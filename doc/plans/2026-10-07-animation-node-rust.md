# 帧动画节点 Rust 处理实施计划

**目标**：完善现有图片帧动画流程：生成/导入、透明清理、稳定锚点、帧编排、预览与导出。
**范围**：用户已确认本批节点、生成入口、Rust、类型/历史、测试和模块文档；补充研究参考项目的提示词与中心对齐。视频转循环、插帧、场景合成不在本批。
**架构**：项目文件保留原始 Sprite Sheet，处理与帧编排为非破坏性参数。预览使用短期 Blob，导出从原图应用相同 Rust 算法，不持久化图片正文或运行时对象。复用 image、serde、既有文件服务与画布派生守卫。
**参考**：aldegad/sprite-gen `ece1ac8b4827d5d8075592471aef5152c371cda9` 的 gen/prepare.py、frames/extract.py、frames/segment.py、compose/compose_atlas.py。保留 Apache-2.0 来源说明及其中 MIT 算法归属。

## 实施顺序

1. Rust：有界解码、绿/品红键控与软边去色、投影分帧、Alpha/脚部锚点与共同缩放；空帧失败关闭，跳跃保留纵向位移。纯算法测试覆盖中心、脚底、软边和异常输入。
2. 提示词：分开描述身份参考与动作参考；锁定像素密度、比例、非对称饰物、朝向、相机；用相对坐标规定中心轴/脚底/安全区，不要求模型绘制引导线。单节点与批量入口使用同一合同。
3. UI/服务：导入原图、处理选项、非破坏性帧排序/启停/偏移；按需加载编辑器，短期预览及时释放；源图格数快照独立于下一次生成参数。
4. 导出：GIF 使用当前循环设置；PNG 序列与图集 JSON 应用相同帧编排。校验真实调用方及每个派生文件路径，拒绝静默覆盖已有文件。
5. 验证：定向 Vitest、前端/测试类型检查、定向 ESLint、cargo test sprite 与 cargo check；记录实际结论及桌面验收缺口。

## 中心稳定边界

- 提示词只降低生成误差，不能保证像素级一致；Rust 用可选择的脚部下 20% Alpha 加权中心或全体 Alpha 质心纠正横向漂移。
- 各帧共同缩放，避免把下蹲或腾空错误放大；默认统一脚底线，jump 默认保留原图纵向轨迹。
- 武器/披风可能影响质心，保留关闭对齐及逐帧偏移；不自动修复肢体、身份或重复姿势。
- 原图不可覆盖，撤销恢复原图引用、参数与编排。浏览器环境可展示原图，原生后处理/导出需要桌面运行时。
